## Phase Boundary

Aplicar los 3 patches quirúrgicos de la Estrategia A del reporte de paridad visual para cerrar el gap entre lo que un humano ve en la SERP de Google y lo que `/search` devuelve. Medición empírica del reporte: parser actual pierde el 38% de productos comerciales con URL canónica.

**In scope (Estrategia A solamente — 3 patches):**
1. **`browser.py:81` switch wait_until** — `domcontentloaded` → `load`. Recupera el Shopping panel `div.pla-unit` que el setting actual corta antes del render.
2. **`search.py` regex precio v2** — fix bug `$410.420,311001` (greedy concat) con cierre obligatorio `,DD` + alt entero para `ARS 5000`/`U$S 5000`.
3. **`search.py` extractor pla-unit** — nueva pasada `_extract_pla_unit()` + `PLA_SELECTORS = ["div.pla-unit"]` aplicada DESPUÉS del carousel (additive, no cascade reemplazo).
4. **Tests + fixtures** — 2 fixtures HTML (robotech + zapatillas) + regex unit tests + smoke runtime de las 5 queries del dataset del reporte.
5. **Harness mínimo** — endpoint `/admin/parity/<query>` con métricas Prometheus básicas. NO el dataset completo de 12 queries todavía (eso es Phase 0.2.2).

**Out of scope explícito:**
- Estrategia B (DOM-driven browser persistente) — viola D8 invariant, no se evalúa en 0.2.1.
- Estrategia C (SerpAPI / Bright Data) — Phase 0.2.4 spike, no se mete en 0.2.1.
- Resolución de URLs reales del carousel via JS-render — cerrado como no viable sin Estrategia B (carousel sigue con URLs sintéticas, que es lo único razonable).
- Paginación page 2 — Phase 0.2.3.
- Dataset de 12 queries del harness continuo — Phase 0.2.2.
- LLM tuning, freshness, cache — fuera del scope del fix de parser.
- Cualquier cambio que rompa D8 (no persistent contexts).

<decisions>
## Implementation Decisions

### Patch 1 — browser.py wait_until switch
- **D-01:** En `src/artiscrapper/browser.py:81`, cambiar `wait_until="domcontentloaded"` por `wait_until="load"`. Bajar `timeout=20_000` a `timeout=15_000` simultáneamente para fail-fast. **Por qué:** evidencia empírica del Exp 2 (5 queries en el reporte) mide 0 → 4 pla-units con switch, dt promedio 3.1s (sin penalty), p100 4.4s (dentro del budget de 15s).
- **D-02:** Mantener `_detect_block` como está — `wait_until="load"` da más tiempo al CAPTCHA/sorry redirect para concretarse en `page.url`, mejor para detección.
- **D-03:** Comentario inline en el código apuntando al reporte: `# PARITY: wait_until="load" recupera Shopping panel... (ver .planning/PARSER-VISUAL-PARITY-2026-06-05.md §2)`. **Por qué:** memoria `feedback_empirical_retest_after_default_changes` — el siguiente debugger debe poder rastrear por qué este valor es distinto del default.

### Patch 2 — Regex precio v2
- **D-04:** Reemplazar `_PRICE_RE` en `src/artiscrapper/search.py:63-66` por la versión validada en el reporte: `(?:\$|ARS|U\$S)\s?(?:&nbsp;)?\s?(?:[1-9]\d{0,2}(?:\.\d{3})*,\d{2}|[1-9]\d{2,7}(?![\d.,]))`. **Por qué:** el regex actual con `[\d.,]*\d` greedy captura `$410.420,311001` cuando el siguiente token es un número (el caso real `$ 410.420,31` + `1001hobbies.es`). El fix exige cierre `,DD` y previene bleeding.
- **D-05:** Mantener compatibilidad con `_normalize_price_text` — la función que strippea NBSP. NO cambiar ese comportamiento.
- **D-06:** Test unit suite cubre los 10 casos del reporte: patológico, cuotas, store con dígitos, ARS sin decimales, U$S 5000, etc.

### Patch 3 — pla-unit extractor + nuevo pass
- **D-07:** Agregar `_extract_pla_unit(node)` en `src/artiscrapper/search.py` siguiendo el prototipo validado en `/tmp/parser_v2.py`. Selectores internos:
  - Título: `[role=heading]` (NO el `aria-label` del `<a>` que viene vacío)
  - URL: primer `<a href>` que NO sea `/aclk?` (los aclk son tracking pixels display:none)
  - Precio: `span.VbBaOe`
  - Store: `div.UsGWMe`
  - Cuota: `div.OkcyVb`
- **D-08:** Agregar `PLA_SELECTORS = ["div.pla-unit"]` y un loop en `parse_serp()` DESPUÉS del carousel (no en cascade del organic). **Por qué:** los pla-units son sponsored ads aditivos al organic + carousel, no reemplazan el bloque organic. Cascade replacement causaría regression en queries donde organic existe pero pla-unit no.
- **D-09:** Dedupe pla-unit por URL DENTRO del bloque (Google a veces duplica el mismo producto en panel y `g-scrolling-carousel` paralelo). El dedupe global (`dedupe()`) ya correrá después y combina con organic.
- **D-10:** Flags `["pla_unit", "sponsored"]` en cada candidate. **Por qué:** el LLM curator + heuristic_pre_classify deben poder distinguir sponsored de organic para futuras políticas (ranking, transparencia con el usuario).
- **D-11:** Si `extract_pla_unit` retorna None (HTML incompleto, falta título o URL canonical), descartar silenciosamente. NO loguear cada miss — el bloque pla-unit puede no estar en el HTML (depende del Google auction). Solo loguear si el HTML tiene `div.pla-unit` pero todos extraen None (signal de selector rotation).

<specifics>
## Specific Ideas

- El precio en el HTML viene con NBSP entre `$` y el número (`$\xa0920.000,00`). El regex v2 y `_normalize_price_text` ya manejan esto.
- Los pla-unit `<a href>` traen muchos `&amp;` en URL (HTML-encoded). Necesario `split("&amp;")[0]` o `html.unescape` antes de retornar.
- Selectolax matchea `[role=heading]` sin namespace tricks — ya verificado.
- Los pla-unit a veces tienen 4 productos solo (robotech), a veces 30 (zapatillas). El loop debe ser robusto a ambos.
- El carousel item con texto `"threezero Figura a escala 1:6 de Robo-Dou$ 410.420,311001hobbies.esy más"` es el caso patológico real del regex bug — incluirlo en el test fixture o inline test string.
