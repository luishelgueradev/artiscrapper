# Phase 0.2.2: Harness de Paridad Visual Continua — Research

**Researched:** 2026-06-05

**Source:** `.planning/PARSER-VISUAL-PARITY-2026-06-05.md` + production smoke runtime (5 queries, ver `0.2.1-02-SUMMARY.md`)

## 1. Por qué este harness existe (recap del reporte)

El parser SERP tiene 3 fuentes de drift potencial, todas externas:

1. **Google rota classes obfuscadas internas** (`VbBaOe`, `UsGWMe`, `OkcyVb`, `[role=heading]`) cada trimestre aprox. Phase 0.2.1 mitigó eligiendo el selector contenedor estructural `div.pla-unit` que es estable, pero los selectores internos del cell sí pueden romperse.
2. **Google cambia el contenedor `div.pla-unit`** entero (low probability, alto impacto). Esto invalida toda la captura del shopping panel.
3. **Cambios upstream en Cloak/Playwright** que afecten `wait_until="load"` (low probability).

Sin harness continuo, ninguno se detecta hasta que un humano nota que `/search` devuelve menos productos. Phase 0.2.1 dejó el endpoint `/admin/parity/{q}` para auditoría manual; 0.2.2 lo automatiza.

## 2. Lo que ya está en producción (foundation)

Phase 0.2.1 cerró:
- `GET /admin/parity/{query:path}` autenticado (X-API-Key) — fetcha SERP via Cloak, parsea, compara con HTML raw
- 2 gauges Prometheus en `src/artiscrapper/metrics.py`:
  - `artiscrapper_parity_pla_units_in_html{query}`
  - `artiscrapper_parity_pla_units_extracted{query}`
- Drift detector inline: si `pla_units_in_html > 0` y `pla_extracted == 0`, response incluye `"drift": ["pla_unit_in_html_not_extracted"]`

Validado prod hoy 2026-06-05 contra 5 queries cross-vertical (juguete, ropa, repuesto, electro, libro). Resultados:

| Query | pla_in_html | pla_extracted | candidates_total | candidates_real_url | drift |
|---|---:|---:|---:|---:|---|
| figura+coleccion+robotech | 11 | 11 | 48 | 18 | [] |
| zapatillas+nike+air+max+hombre+42 | 30 | 30 | 39 | 39 | [] |
| filtro+aceite+ford+focus | 6 | 6 | 41 | 11 | [] |
| termotanque+rheem+80+litros | 30 | 30 | 70 | 40 | [] |
| harry+potter+tapa+dura | 30 | 30 | 68 | 38 | [] |

100% extraction rate cuando hay pla; cero drift en las 5 queries. **Este es el baseline.**

### 3.2 Métricas Prometheus completas (HARNESS-02)

Tres nuevas en `metrics.py`:

```python
# Gauge — coverage_pct depends on min_expected which is fixed per-query;
# resetting the gauge value on every audit gives Prometheus a "current state"
# read which is what alerts and dashboards want.
parity_coverage_pct = Gauge(
    "artiscrapper_parity_coverage_pct",
    "Real-URL coverage percent (clamped 0..100) for the last audited query",
    ["query"],
)

# Counter — `_missed` is monotonic. Each audit increments by max(0, pla_in_html - pla_extracted).
# Why Counter not Gauge: alerts are interested in "did this rise?" not "current snapshot".
parity_pla_units_missed = Counter(
    "artiscrapper_parity_pla_units_missed_total",
    "Total pla-units present in HTML but missed by parser (drift signal)",
    ["query"],
)

# Gauge — synthetic URL fraction is a current-state metric; carousel synthetic URLs
# are NORMAL (Strategy A doesn't resolve them). High values just mean Google served
# heavy carousel for that query. Watch for SUDDEN changes vs absolute level.
parity_url_synthetic_ratio = Gauge(
    "artiscrapper_parity_url_synthetic_ratio",
    "Fraction of candidates whose URL is a Google synthetic (carousel)",
    ["query"],
)
```

Update site: `src/artiscrapper/main.py` inside `admin_parity` and in the new `_parity_audit_sample` task. Both call a shared helper that computes the 3 metrics from `(html, candidates, expected_min)` and sets all gauges.

### 3.3 Sample 1/10 sobre hot path (HARNESS-03)

Approach: in `POST /search`, AFTER the response is generated, schedule a bg task. The bg task reuses the HTML already in the cache (no extra Google fetch). Sample rate = `settings.PARITY_SAMPLE_RATE` (default 0.1).

Implementation sketch:

```python
# src/artiscrapper/main.py — inside POST /search, before return SearchResponse

import random
if random.random() < settings.PARITY_SAMPLE_RATE:
    task = asyncio.create_task(_parity_audit_sample(query, html))
    _PARITY_BG_TASKS.add(task)
    task.add_done_callback(_PARITY_BG_TASKS.discard)


async def _parity_audit_sample(query: str, html: str) -> None:
    """Reuse the cached HTML from /search and run the parity audit metrics.
    Overhead expectation: <50ms p99 (DOM parse + regex counts on cached HTML).
    NEVER raises — failure is logged structurally and discarded.
    """
    try:
        _set_parity_metrics(query, html)
    except Exception as exc:
        log.warning("parity_sample_failed", query=query[:80], error=str(exc))
```

`_set_parity_metrics(query, html)` is the shared helper — it runs the same parsing + comparison logic as `admin_parity` BUT without re-fetching Google. It updates all 5 gauges + counter.

**Critical:** the lookup for `min_expected_real_urls` per query has to be fast (load YAML once at module import, dict-by-id). If the query doesn't exist in the dataset (most production queries won't), use `0` for min_expected and just record raw counts without coverage_pct (skip the coverage gauge update).

### 3.4 CI nightly (HARNESS-04)

`.github/workflows/parity-nightly.yml`:

```yaml
name: Parity nightly audit
on:
  schedule:
    - cron: "0 3 * * *"   # 3am UTC = midnight ART, low-traffic window
  workflow_dispatch:       # manual run capable

jobs:
  audit:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
      - name: Verify secret present
        run: |
          if [ -z "${{ secrets.ARTISCRAPPER_NIGHTLY_KEY }}" ]; then
            echo "::error::ARTISCRAPPER_NIGHTLY_KEY secret missing"
            exit 1
          fi
      - name: Build + start
        env:
          API_KEYS: "${{ secrets.ARTISCRAPPER_NIGHTLY_KEY }}"
        run: |
          docker compose build
          docker compose up -d
      - name: Wait for healthy
        run: |
          for i in $(seq 1 90); do
            if curl -fs http://localhost:8001/health > /dev/null 2>&1; then
              echo "Healthy after ${i}s"
              break
            fi
            sleep 1
          done
      - name: Run dataset
        env:
          API_KEY: "${{ secrets.ARTISCRAPPER_NIGHTLY_KEY }}"
        run: |
          .venv/bin/python scripts/run_parity_nightly.py \
            --dataset tests/fixtures/parity-dataset.yaml \
            --endpoint http://localhost:8001/admin/parity \
            --threshold 75 \
            --api-key "$API_KEY" \
            --summary "$GITHUB_STEP_SUMMARY"
      - name: Logs on failure
        if: failure()
        run: docker compose logs --tail=100
      - name: Teardown
        if: always()
        run: docker compose down --volumes
```

`scripts/run_parity_nightly.py` reads the YAML, loops queries, calls the endpoint, agregates coverage, prints markdown table to stdout (which GitHub Actions writes to summary), and exits 1 if avg coverage < threshold or any query returns blocked.

### 3.5 Alertas Prometheus (HARNESS-05)

`prometheus/alerts/parity.yaml`:

```yaml
groups:
  - name: artiscrapper-parity
    interval: 1m
    rules:
      - alert: ParityCoverageWarn
        expr: avg_over_time(artiscrapper_parity_coverage_pct[30m]) < 75
        for: 30m
        labels: { severity: warning }
        annotations:
          summary: "artiscrapper parity coverage degraded for {{ $labels.query }}"
          description: |
            Average parity coverage over 30min is {{ printf \"%.0f\" $value }}% (threshold 75).
            Investigate: /admin/parity/{{ $labels.query }} returns drift flags or low candidates_real_url.
      - alert: ParityCoverageFail
        expr: avg_over_time(artiscrapper_parity_coverage_pct[5m]) < 50
        for: 5m
        labels: { severity: critical }
        annotations:
          summary: "artiscrapper parity coverage CRITICAL for {{ $labels.query }}"
          description: "Coverage is {{ printf \"%.0f\" $value }}% — likely class rotation by Google or upstream Cloak breaking. Investigate immediately."
      - alert: ParityPlaUnitsMissed
        expr: increase(artiscrapper_parity_pla_units_missed_total[15m]) > 5
        for: 5m
        labels: { severity: warning }
        annotations:
          summary: "artiscrapper detected pla-units missed by parser ({{ $labels.query }})"
          description: |
            {{ $value }} pla-units present in HTML but not extracted in last 15min.
            Strong signal Google rotated internal classes (VbBaOe / UsGWMe / OkcyVb / [role=heading]).
```

## 4. Riesgos identificados + mitigación

| Riesgo | Probabilidad | Mitigación |
|---|---|---|
| Sample 1/10 add p99 latency >50ms | Baja (DOM parse only ~10ms en 1.5 MB HTML) | Bench mandatorio en plan; `PARITY_SAMPLE_RATE=0` desactiva si necesario |
| GitHub Actions secret no presente al primer run | Alta si Luis no se acuerda | Workflow falla con mensaje explícito en step 1 |
| Cloak inside CI runner falla (recursos VM) | Media | timeout-minutes: 30 + docker compose down --volumes en teardown |
| Métricas con label `query` explotan cardinality | Baja (12 queries fijas + truncado a 80 chars en hot path) | Documentar limit en código + alert si > 100 series |
| `min_expected_real_urls` calibrado mal castiga rondas válidas | Media | Empezar con 50% del baseline; ajustar después de 2 semanas de nightly stable |
