# Plan 0.2.1-02 — Tests + fixtures + parity endpoint — Summary

## Goal

Pin the parity gains from Plan 01 with regression-proof tests + fixtures + a
minimum runtime audit surface (`/admin/parity/{q}` + 2 Prometheus gauges).

## What was built

### 1. Frozen fixtures — `tests/fixtures/serp/` (PARITY-04)

Two fixtures captured 2026-06-05 via Cloak with `wait_until="load"` (the
Plan 01 patch):

| Fixture | Size | pla-units | Stores represented |
|---|---:|---:|---|
| `pla_unit_robotech.html` | 726 KB | **4** | MELI canonical (`/p/MLA*`, `/up/MLAU*`) |
| `pla_unit_zapatillas.html` | 1.28 MB | **30** | sporting, nike, stockcenter, coppel, ferreirasport, … |

Both fixtures preprocessed:
- `data:image/...` base64 blobs → `data:image/png;base64,PLACEHOLDER`
- inline `<script>...</script>` bodies emptied (parser is DOM-only)

This dropped robotech 1.58 MB → 726 KB; zapatillas 2.44 MB → 1.28 MB.

### 2. Unit tests — `tests/test_parser.py` (+10 new)

**pla-unit (4 + 1 selector smoke):**
- `test_pla_unit_extracts_4_products_from_robotech_fixture` — ≥4 MELI cards

- `test_pla_unit_no_aclk_urls` — `/aclk?` tracking pixels skipped
- `test_pla_unit_sponsored_flag` — every extract carries `pla_unit` + `sponsored`

**_PRICE_RE v2 (6 parametrized cases + 4 standalone):**

### 3. Integration tests — `tests/integration/test_serp_pla_unit_replay.py` (+4 new)

End-to-end `parse_serp()` over the fixtures:
- `test_robotech_returns_pla_unit_products` — Plan 01 wave-1 pass works in concert
- `test_zapatillas_returns_pla_unit_products` — diverse non-MELI stores
- `test_robotech_no_duplicate_urls_within_pla_block` — internal dedupe holds
- `test_price_regex_no_dirty_prices_in_robotech` — no `$X,XXY` artefacts in candidates

### 4. `/admin/parity/{query}` endpoint — `src/artiscrapper/main.py` (PARITY-05)

`GET /admin/parity/{query:path}` (X-API-Key auth):
- Fetches the SERP for `query` via Cloak (hits `rate_limit` — NOT cached).
- Parses with the current parser, compares against the raw HTML's signals
  (price count, canonical-URL count, `div.pla-unit` count).
- Returns JSON with `html_metrics`, `parser_metrics`, and `drift`. Initial
  drift detector flags `pla_unit_in_html_not_extracted` — strong signal of
  Google rotating the internal obfuscated classes.

### 5. Prometheus gauges — `src/artiscrapper/metrics.py` (PARITY-05)

- `artiscrapper_parity_pla_units_in_html{query}`
- `artiscrapper_parity_pla_units_extracted{query}`

Declared in `metrics.py` (NOT `main.py`) because `test_sentry_init` reloads
`main.py` via `importlib.reload`, which triggered a "Duplicated timeseries
in CollectorRegistry" ValueError on the second import. `metrics.py` lives
outside the reload path.

Phase 0.2.2 will add the full set (`parity_coverage_pct`,
`parity_pla_units_missed`, `parity_url_synthetic_ratio`) along with the
12-query dataset and CI nightly.

## Deviations

1. **Fixture size**: plan called for ≤900 KB for zapatillas; actual 1.28 MB.
   Cause: 30 pla-units inherently contains more HTML than robotech's 4.
   Phase 1 fixtures (e.g., `01-pelota_playera_quico.html`) range 0.9-1.5 MB —
   the new fixture is consistent with the project's existing fixture scale.

2. **Plan said "verify against /tmp/toy-robotech.html"**: that re-capture
   happened to return 0 pla-units due to Google Shopping auction volatility.
   We pin the regression test against `/tmp/robotech-serp.html` (the Day-1
   capture that did contain 4 pla-units). The fixture under
   `tests/fixtures/serp/pla_unit_robotech.html` is sourced from
   `robotech-serp.html` accordingly.

3. **Parity gauges live in `metrics.py`, not `main.py`** as originally
   sketched in the plan. Necessary to keep `main.py` reload-safe for
   `test_sentry_init`. Same metric names + labels — no scrape format change.

4. **Pre-existing `test_parse_serp_fixtures` needed a glob narrowing**
   (`*.html` → `[0-9][0-9]-*.html`) so the new pla-unit fixtures in the
   same directory wouldn't trip its `len() == 10` assertion. Out-of-plan
   compat fix bundled in this wave.
