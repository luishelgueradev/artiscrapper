### Pattern 1: Surgical rename with sister-method audit

**What:** When a library deprecates a property name in favor of a new one, search ALL usages in the codebase, not just the one that triggered the warning. tldextract is used in 2 source files; only 1 calls the deprecated property.

**When to use:** TECHDEBT-01.

**Example:**

```python

if ext.registered_domain.lower() in _MELI_REGISTERED_DOMAINS:
    candidate["flags"] = candidate.get("flags", []) + ["meli_skip"]

# AFTER
ext = tldextract.extract(url)
if ext.top_domain_under_public_suffix.lower() in _MELI_REGISTERED_DOMAINS:
```

### Pattern 2: Framework-default fast path (ORJSONResponse removal)

**What:** FastAPI 0.131+ deprecated `ORJSONResponse` because Pydantic v2's Rust-based JSON serializer is now the default fast path for routes with `response_model`/return-type annotations. Removing `default_response_class=ORJSONResponse` does not slow `/search` (the one route with `response_model=SearchResponse`); it speeds it up because the Pydantic-Rust path is faster than the Python-level ORJSONResponse wrap.

**When to use:** TECHDEBT-02.

**Example:**

```python
# BEFORE — src/artiscrapper/main.py:28, 243-248
from fastapi.responses import ORJSONResponse
...
app = FastAPI(
    lifespan=lifespan,
    default_response_class=ORJSONResponse,   # ← deprecated
    title="artiscrapper",
    version=settings.VERSION,
)

# AFTER
# (remove the ORJSONResponse import)
...
app = FastAPI(
    lifespan=lifespan,
    title="artiscrapper",
    version=settings.VERSION,
)
```

**Endpoints affected (all 4 OK with default behavior):**

| Endpoint | Return type | Behavior after removal |
|----------|-------------|------------------------|
| `GET /health` | `dict` | FastAPI wraps in default `JSONResponse` (stdlib json) — was previously wrapped in `ORJSONResponse`. Performance delta on a 4-field dict is below measurement noise. |
| `GET /health/deep` | `dict` | Same as above. |
| `GET /admin/parity/{query}` | `dict` (8 nested keys) | Same as above. Not on hot path. |
| `POST /search` | `SearchResponse` (via `response_model`) | Pydantic-Rust path (faster than ORJSONResponse). This is the one perf-critical route and it gets faster, not slower. |

### Anti-Patterns to Avoid

- **Pinning tldextract `<5.3.0` to dodge the warning.** Regresses to a version without the deprecation but also without the new property name; locks us out of the 6.0 path. Don't.
- **Editing test files to make TestClient work with httpx2.** Unnecessary — starlette does the import switch internally. Adding `import httpx2` anywhere in `tests/` is noise.
- **Replacing `default_response_class=ORJSONResponse` with a custom 4-line ORJSONResponse class (the "self-host the implementation" path from PR #14964).** It buys nothing on Python 3.13 + Pydantic v2 + FastAPI 0.136 — the Rust serializer is already the default fast path. Reserve self-hosting for the case where benchmarks prove a real regression.
- **Adding `-W ignore::DeprecationWarning` to mask all four warnings at once.** Defeats the purpose — TECHDEBT-03's success criterion explicitly demands `pytest -q -W error::DeprecationWarning -m "not slow"` exits 0. Per-warning filter (last-resort only) is acceptable; blanket ignore is not.
- **Excluding `scripts/spike/` from ruff entirely.** Loses regression coverage if any spike script is revived (e.g., a new Phase 1-style empirical-validation cycle). Fix-in-place is cheap.

## Common Pitfalls

### Pitfall 1: tldextract has *two* sister properties — easy to grab the wrong one

**What goes wrong:** When renaming `.registered_domain`, you find `.top_domain_under_public_suffix` AND `.top_domain_under_registry_suffix` in the docs. They are different. Picking the registry-suffix version changes private-domain behavior (Blogspot, GitHub Pages, etc.).

**Why it happens:** Both names are similar; the original `registered_domain` was renamed only to one of the two — the public-suffix one.

**How to avoid:** Use `top_domain_under_public_suffix` (the explicit replacement per the deprecation warning). Do NOT use `top_domain_under_registry_suffix` — that one is a different semantic.

**Warning signs:** Test `test_meli_guard_no_false_positive_on_notmercadolibre` PASS but the live `articulo.mercadolibre.com.ar` flow start failing in production — that would mean private-suffix handling diverged.

### Pitfall 2: ORJSONResponse import lingering after removal

**What goes wrong:** Remove the `default_response_class=ORJSONResponse` line at `main.py:245` but forget the `from fastapi.responses import ORJSONResponse` at `main.py:28`. Ruff flags F401 unused-import; mypy may warn too.

**Why it happens:** Two-step edit; easy to miss step 2.

**How to avoid:** Verify with `ruff check src/artiscrapper/main.py` after the edit.

**Warning signs:** F401 error in the post-edit lint pass.

### Pitfall 3: httpx2 install marked `[SUS]` by slopcheck

**What goes wrong:** Operator sees `slopcheck` flag `[SUS]` on `httpx2`, panics, and reaches for the `-W ignore::DeprecationWarning` filter instead.

**Why it happens:** httpx2 is genuinely new (25 days old at research time) and lives at a name suspiciously close to `httpx` — the exact typosquat shape.

**How to avoid:** Run the 3 verification commands listed in the Package Legitimacy Audit section. The decisive evidence is that **starlette itself imports `httpx2` by name inside our installed `.venv`** — that is dispositive proof that the package name is real and was authored against by the starlette/fastapi maintainers.

**Warning signs:** If `grep 'import httpx2' .venv/lib/python3.13/site-packages/starlette/testclient.py` returns no matches, STOP — that would mean starlette has rolled back the change and httpx2 install is no longer necessary.

### Pitfall 4: `-W error::DeprecationWarning` surfaces warnings from third-party libs we don't own

**What goes wrong:** After fixing TECHDEBT-01, -02, -03, the gate command still fails because some other transitive dep emits a `DeprecationWarning` (e.g., pydantic, prometheus-client, cloakbrowser).

**Why it happens:** Errorifying all `DeprecationWarning`s exposes every transitive dep, not just ours.

**How to avoid:** Run `pytest -q -W error::DeprecationWarning -m "not slow"` once, BEFORE filing any code edits, to enumerate the full surface of warnings. The current run shows only 2 root causes (tldextract + starlette/httpx2 + the ORJSONResponse FastAPI warning is non-fatal because it surfaces inside `routing.py` and not at boundary). If new warnings appear, add **narrow** per-module ignores via `filterwarnings = ["error::DeprecationWarning", "ignore::SomeWarning:offending.module"]` — never a blanket `ignore`.

**Warning signs:** A green `pytest -q -m "not slow"` but a red `pytest -q -W error::DeprecationWarning -m "not slow"` with a warning from a module other than `tldextract`, `starlette`, or `fastapi.routing`.

### Pitfall 5: scripts/spike `ruff --fix` autofix is unsafe-fixes-disabled by default

**What goes wrong:** `ruff check --fix scripts/spike/` reports "28 fixable; 5 hidden fixes can be enabled with the `--unsafe-fixes` option" and leaves the unsafe ones unaddressed. Operator assumes done; runs the verification command; still 11 errors.

**Why it happens:** Ruff splits fixes into safe and unsafe; default is safe-only.

**How to avoid:** Plan explicitly for both passes. After safe `--fix`, the residue is 5 × E741 (ambiguous `l`) and 6 × F841 (unused locals). Decide per the discretion: per-file-ignore (low touch) OR source rename (`l` → `line`, drop unused vars).

**Warning signs:** `ruff check scripts/spike/` still reports errors after `--fix`.
