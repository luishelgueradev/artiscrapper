# Phase 0.2.5 Plan 01: tldextract `.registered_domain` rename Summary

Renamed the deprecated `tldextract.extract(url).registered_domain` access to the public-suffix-aware sister property `top_domain_under_public_suffix` at the single in-codebase callsite (`src/artiscrapper/visit.py:364`), updated three prose references (module docstring, inline comment, test docstring), and added a one-line defensive comment to `metrics.py` so a future maintainer does not reintroduce the deprecated alias there. Behavior-equivalent on every URL the MELI guard handles (verified empirically by RESEARCH §Code Examples TECHDEBT-01).

## One-liner

Closed TECHDEBT-01 via surgical rename of `tldextract.registered_domain` → `top_domain_under_public_suffix` at `visit.py:364` plus a forward-defense comment in `metrics.py`; suite stays at 124-pass baseline and the WR-01 MELI-guard invariant remains green.

## Decisions Made

1. **Rename to `top_domain_under_public_suffix`, NOT `top_domain_under_registry_suffix`.** The deprecation message itself names `top_domain_under_public_suffix` as the replacement, and the registry-suffix variant has different semantics for private suffixes (blogspot.com, github.io) that would regress the WR-01 invariant. Pinned by the threat-register row T-0.2.5-01.
2. **Defensive comment in `metrics.py` (RESEARCH Q4).** The file does not currently call `.registered_domain` (it uses `ext.domain + ext.suffix` directly), so no behavior change is required — but the visit.py rename pattern is exactly the kind of thing a future refactor could re-introduce here. The single `# NOTE:` line is cheap insurance and was the locked-in choice from RESEARCH Open Question 4.
3. **No `-W ignore::DeprecationWarning`.** Silencing the warning would defeat TECHDEBT-03's always-on `filterwarnings = ["error::DeprecationWarning"]` gate (Plan 03). The surgical rename is the only forward-compatible option (RESEARCH Anti-Patterns).
4. **No `tldextract<5.3.0` pin.** Pinning down is a regression and freezes the project on an older public-suffix list. The rename is provably behavior-equivalent and forward-compatible with 6.0 whenever it ships.
