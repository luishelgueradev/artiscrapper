## Decisions Made

- **Local var renamed `results` → `fetch_results`** in the gather call to avoid shadowing the outer `results` list that is later rebound (~line 940) for the response `Candidate` list. The outer one is reassigned before being read so the original code wasn't buggy, but the rename removes a readability smell. (Documented under "Claude's discretion" in CONTEXT D-06 — loop structure exact.)
- **All-or-nothing on exception** (CONTEXT D-06): a single fetch raising an exception still aborts the entire /search, matching prior 2-fetch semantics. Partial-success is explicitly out of scope per the CONTEXT.
- **First non-None block_reason wins** (`next((b for b in blocks if b), None)`): semantically identical to `block_a or block_b` of the prior code, generalized for N fetches.
- **`fetch_coros` built as a flat list, not paired tuples**, then unpacked into `asyncio.gather(*fetch_coros)`. Simpler than maintaining a parallel `fetch_specs` (page, meli, url) telemetry list which the plan suggested but isn't used downstream — kept lean per Luis's "no acopladas" philosophy.
- **Setting name kept as `SEARCH_FETCH_PAGES`** (D-03 suggested it; no clearer alternative emerged during execution).
